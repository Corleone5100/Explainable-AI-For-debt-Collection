1. GRAPH CONSTRUCTION (graph_builder.py)
================================================================================

WHAT IS THE GRAPH?
------------------
The system builds a **borrower contagion graph** - a network where each node 
represents an individual borrower, and edges represent potential "contagion links" 
that could spread financial risk between similar borrowers.

NODES:
------
Each node represents a **borrower** (loan account holder). The dataset contains 
up to 200,000 borrowers loaded from a PostgreSQL database (table: master_env_data).

Each node has 8 features (node attributes):
  - age: Borrower's age
  - income: Monthly/yearly income
  - cibil_score: Credit score (300-900 range)
  - overdue_months: Number of months the loan is overdue
  - bounce_count: Number of payment bounces/defaults
  - coll_success_rate: Historical collection success rate for assigned collector
  - occ_idx: Occupation encoded as numeric index
  - reg_idx: Region encoded as numeric index

EDGES (How the Graph is Connected):
------------------------------------
Edges are created based on **social contagion theory** - the idea that borrowers 
who share similar socioeconomic characteristics may influence each other's 
financial behavior.

Edge Creation Logic:
  - Group borrowers by (region, occupation) pairs
  - Within each group, create edges between members (clique-like structure)
  - For scalability, each borrower connects to up to 5 random neighbors 
    within the same group (sparse connectivity)
  - This keeps the graph sparse while preserving contagion pathways

Example: If 50 borrowers are all "Salaried" workers in "Region R1", they form 
a connected subgraph where each borrower is linked to 5 random peers from 
that same group.

GRAPH STRUCTURE SUMMARY:
-------------------------
- Type: Undirected homogeneous graph (single node/edge type)
- Nodes: Up to 200,000 borrowers
- Edges: Variable, but approximately 5 * num_nodes (sparse)
- Features per node: 8 continuous/categorical features (scaled)
- Framework: PyTorch Geometric (PyG) Data object

GRAPH FEATURE EXTRACTION:
--------------------------
After building the graph, the system computes a **neighborhood stress signal** 
for each borrower:
  - This simulates a single GNN message-passing step
  - For each borrower, it calculates the average overdue_months of their 
    connected neighbors
  - This signal represents "contagion risk" - how much financial stress 
    surrounds this borrower in the network
  - The signal is saved as 'neighborhood_stress_signal' in the CSV file 
    (rl_ready_with_graph_features.csv)

This neighborhood signal becomes a critical feature for the RL agent, 
providing network-level intelligence that traditional tabular models would miss.

2. REINFORCEMENT LEARNING ENVIRONMENT (debt_env.py)
================================================================================

THE ENVIRONMENT: DebtCollectionEnv
------------------------------------
The environment is a Gymnasium-compatible simulation that models the debt 
collection process. An RL agent (PPO) learns to select optimal collection 
actions for each borrower.

OBSERVATION SPACE (State):
---------------------------
Each observation is a 10-dimensional vector representing the current borrower:
  [0] income
  [1] cibil_score
  [2] overdue_months
  [3] bounce_count
  [4] coll_success_rate
  [5] neighborhood_stress_signal  <-- Graph-derived feature (key innovation)
  [6] age
  [7] occ_idx (occupation index)
  [8] reg_idx (region index)
  [9] padding (0.0)

ACTION SPACE:
--------------
Discrete space with 4 possible actions:
  Action 0: No Action (do nothing)
  Action 1: SMS/Call (digital communication)
  Action 2: Field Visit (physical collector visit)
  Action 3: Legal Notice (formal legal action)

REWARD FUNCTION (How the Agent Learns):
----------------------------------------
The reward is a sophisticated function that balances recovery gains against 
action costs:

1. ACTION COST (negative reward):
   - No Action: 0
   - SMS/Call: 30-80 (varies by risk category)
   - Field Visit: 300-500
   - Legal Notice: 250-800

2. RECOVERY AMOUNT (positive reward):
   - Success probability depends on:
     * Base recovery rate (varies by action and risk category)
     * Collector's success rate
     * Neighborhood stress signal (higher stress = lower success)
   - If successful, recovered amount is a percentage of total_demand:
     * SMS: 5-15% of demand
     * Field Visit: 15-35% of demand
     * Legal: 20-40% of demand

3. PENALTY FOR MISMATCHED ACTIONS (negative reward):
   - Field Visit/Legal on Very Low risk: Large penalties (wasteful spending)
   - No Action/SMS on High/Very High risk: Penalties (missed opportunity)
   - These penalties teach the agent to match action intensity to risk level

RISK CATEGORIES:
-----------------
The system uses 5 risk tiers that influence reward dynamics:
  - Very Low: Cheap actions work well; expensive actions are wasteful
  - Low: Moderate response to SMS/Calls
  - Medium: Balanced response across actions
  - High: Requires aggressive action (Field Visit/Legal)
  - Very High: Most difficult to collect; needs Legal/Field Visit

THE ALGORITHM: PPO (Proximal Policy Optimization)
---------------------------------------------------
The system uses PPO, a state-of-the-art policy gradient algorithm from 
Stable Baselines3.

Why PPO?
  - Stable training compared to other policy gradient methods
  - Good sample efficiency for this type of environment
  - Handles continuous action spaces well (even though discrete here)
  - Less prone to catastrophic policy collapses

Training Configuration:
  - Algorithm: PPO (MlpPolicy - uses standard neural network, not GNN)
  - Learning rate: 0.0003
  - Steps per update: 2048
  - Total timesteps: 500,000
  - Device: CUDA (GPU accelerated)
  - Environment wrapping: DummyVecEnv + VecNormalize

VecNormalize:
  - Normalizes observations and rewards to stabilize training
  - Critical because features have vastly different scales 
    (income: thousands, CIBIL: 300-900, graph signal: 0-12)
  - Both the model AND normalization stats are saved for inference

EPISODE STRUCTURE:
-------------------
- Each episode processes 100 borrowers sequentially
- Borrowers are sampled randomly from the dataset
- The agent receives the observation, selects an action, gets reward + next state
- Training continues for 500,000 total timesteps

================================================================================
3. OVERALL REPOSITORY WORKFLOW
================================================================================

DATA GENERATION PIPELINE:
--------------------------
Step 1: Sample_Data_Generaton.py
  - Creates PostgreSQL database (debt_market_db)
  - Generates synthetic borrower profiles with realistic socioeconomic logic
  - S1 features: age, occupation, income, region, qualification, CIBIL
  - S2 features: overdue_months, bounce_count, demand amounts, risk_category
  - Inserts 20,000+ records into customer_profiles table
  - Uses probabilistic models (e.g., Salaried workers more likely Graduates)

Step 2: loan_collector.py
  - Creates 500 debt collector profiles with varying capabilities
  - Collectors have tiers (Excellent/Average/Irregular), regions, specializations
  - Merges borrowers + collectors into master_env_data table
  - Matching logic: same region + same risk specialization
  - Adds coll_success_rate to each borrower record

ANALYSIS & VISUALIZATION:
---------------------------
Step 3: socioeconomic_analysis.py
  - Visualizes occupation distribution, income by occupation, age vs income, 
    region distribution
  - Validates the synthetic data generation logic

Step 4: correlation.py
  - Computes correlation matrix of key features
  - Identifies key state drivers for risk
  - Generates heatmap visualization

Step 5: risk_analysis.py
  - Analyzes CIBIL score spread per risk category
  - Scatter plot of bounces vs overdue months
  - Call response analysis by risk category
  - Total demand distribution

GRAPH & RL PIPELINE:
---------------------
Step 6: graph_builder.py
  - Loads master_env_data from PostgreSQL (200,000 records)
  - Builds contagion graph using region + occupation grouping
  - Computes neighborhood stress signal (graph feature)
  - Exports rl_ready_with_graph_features.csv

Step 7: debt_env.py
  - Loads the graph-enhanced CSV
  - Creates Gymnasium environment with 4-action space
  - Trains PPO agent for 500,000 timesteps
  - Saves trained model (graph_rl_debt_model.zip) and normalization stats 
    (vec_normalize.pkl)

Step 8: testing.py
  - Loads the trained model and normalization stats
  - Tests the agent on unseen borrowers
  - Evaluates collection strategy effectiveness

OTHER FILES:
-------------
- Synthetic_Data.py: Alternative/earlier data generation script
- figures/: Contains all generated visualization PNGs
  - age_vs_income.png, occupation_distribution.png, correlation_matrix.png,
    risk_vs_cibil.png, bounces_vs_overdue.png, call_status_by_risk.png,
    total_demand_distribution.png, income_by_occupation.png, 
    region_distribution.png

ARCHITECTURAL INNOVATION:
---------------------------
This project's key innovation is the **Graph + RL hybrid**:
  1. Graph neural concepts provide "neighborhood intelligence" to the RL agent
  2. The RL agent learns collection strategies that account for social contagion
  3. Traditional RL would only see individual features; this system also sees 
     network-level risk signals
  4. The result is a more sophisticated debt collection strategy that considers 
     both individual borrower characteristics AND their social network context

TECHNOLOGY STACK:
------------------
- Database: PostgreSQL
- Data Processing: Pandas, NumPy, SQLAlchemy
- Graph ML: PyTorch Geometric, torch_scatter
- RL: Gymnasium, Stable Baselines3 (PPO)
- Visualization: Seaborn, Matplotlib
- Synthetic Data Generation: Custom probabilistic models
