PART A: WHY EXPLAINABILITY MATTERS FOR THIS PROJECT
================================================================================

Your project is called "Explainable AI for Debt Collection." But currently,
there is NO actual explainability component. Here's why it's critical:

1. REGULATORY COMPLIANCE
   Financial AI systems in many jurisdictions (EU AI Act, US CFPB guidelines,
   RBI India) require decisions affecting consumers to be explainable.
   A debtor has the right to know WHY a particular collection action was chosen.

2. TRUST & ADOPTION
   Collection managers won't trust a black-box RL agent that says "use Legal
   Notice for this borrower" without understanding the reasoning.

3. DEBUGGING & IMPROVEMENT
   If the RL agent makes a bad decision, you need to know WHY:
   - Was it the GNN embedding misleading it?
   - Was it over-weighting a particular feature?
   - Was the reward function misaligned?

4. RESEARCH VALIDATION
   A paper titled "Explainable AI for Debt Collection" MUST include:
   - Feature importance analysis
   - Decision-level explanations
   - Counterfactual examples
   Without these, the "Explainable" in the title is unjustified.

5. BIAS DETECTION
   Does the RL agent systematically treat certain occupations or regions
   more harshly? Explainability tools can reveal this.

XAI TECHNIQUE 1: SHAP Analysis on RL Decisions
────────────────────────────────────────────────
WHAT IT IS:
  SHAP (SHapley Additive exPlanations) decomposes any model's output into
  the contribution of each input feature using cooperative game theory.

  For a single decision, SHAP tells you:
    "The RL agent chose 'Legal Notice' because:
     - CIBIL score contributed -0.3 (low CIBIL pushed toward legal)
     - Neighborhood stress contributed +0.2 (risky neighbors)
     - Income contributed +0.1 (low income → less responsive to SMS)
     - GAT embedding dim 7 contributed +0.15 (encodes high-risk cluster)"

HOW IT WORKS:
  SHAP computes Shapley values from cooperative game theory:

    φ_i(v) = Σ_{S ⊆ N\{i}} |S|! * (|N|-|S|-1)! / |N|! * [v(S ∪ {i}) - v(S)]

  In practice, KernelSHAP approximates this by:
    1. Taking the observation vector x (34 dimensions)
    2. Randomly masking subsets of features
    3. Running the masked observation through the RL policy
    4. Measuring how much each feature's absence changes the action
       probabilities

WHAT IT EXPLAINS:
  - Global: Which features matter MOST across all decisions?
  - Local: Why did the agent choose THIS action for THIS borrower?
  - Directional: Did a feature push toward or away from a specific action?

WHY IT MATTERS FOR YOUR PROJECT:
  - Directly answers: "Why did the RL agent recommend Field Visit instead
    of SMS for borrower ACC_12345?"
  - Proves the GNN embeddings actually influence decisions (or reveals
    they don't — which is also valuable)
  - Shows whether the agent learned meaningful patterns or spurious
    correlations

XAI TECHNIQUE 2: Counterfactual Explanations
────────────────────────────────────────────
WHAT IT IS:
  A counterfactual answer to: "What MINIMAL changes to this borrower's
  profile would have led to a DIFFERENT action?"

  Example output:
    "Current decision: Legal Notice
     Counterfactual: If CIBIL score were 680 instead of 520, the agent
     would have chosen SMS/Call instead.
     Minimum change needed: +160 CIBIL points OR -3 overdue months"

HOW IT WORKS:
  Algorithm (gradient-based counterfactual search):
    1. Start with the borrower's actual observation x
    2. The RL policy outputs action probabilities π(a|x)
    3. Define a target action a_target (e.g., "SMS" instead of "Legal")
    4. Optimize a counterfactual x' that:
       a. Maximizes π(a_target | x')
       b. Minimizes distance ||x' - x|| (minimal changes)
       c. Respects feature constraints (e.g., age can't decrease)

    Loss function:
      L(x') = -log(π(a_target | x')) + λ * ||x' - x||_1 + constraints

  For categorical features (occupation, region), use one-hot relaxation
  and round to nearest valid category.

WHAT IT EXPLAINS:
  - "What would need to change for a different outcome?"
  - Actionable recourse for debtors: "Pay 2 months overdue → lighter action"
  - Feature sensitivity: Which features are decision boundaries?

WHY IT MATTERS:
  - Provides DEBTOR-FACING explanations (not just analyst-facing)
  - Shows the agent's decision boundaries are reasonable
  - Enables "what-if" scenario planning for collection managers
  - Directly supports the "Explainable" claim in your project title

XAI TECHNIQUE 3: GNN Explainability (GNNExplainer / Attention Analysis)
───────────────────────────────────────────────────────────────────────
WHAT IT IS:
  Since you're using a GAT (Graph Attention Network), you have TWO
  sources of explainability for the graph component:

  A) ATTENTION WEIGHTS (built-in, free):
     The GAT learns attention coefficients α(i,j) for each neighbor j
     of node i. These directly tell you WHICH neighbors influenced
     this node's embedding the most.

     Example:
       "Borrower ACC_12345's GAT embedding was most influenced by:
        - Neighbor ACC_67890 (attention weight: 0.35) — Very High risk
        - Neighbor ACC_23456 (attention weight: 0.28) — High risk
        - Neighbor ACC_78901 (attention weight: 0.15) — Medium risk"

  B) GNNExplainer (post-hoc):
     For any GNN prediction, GNNExplainer finds:
       - Which input features (among the 8 node features) matter most?
       - Which edges (connections) matter most?

     It produces a subgraph explanation:
       "The GAT classified this borrower as High Risk because of
        a 3-node subgraph involving their top 2 influential neighbors,
        driven primarily by overdue_months and bounce_count features."

HOW IT WORKS:

  A) Attention Weights (from GAT):
     During GAT forward pass:
       α(i,j) = softmax(LeakyReLU(a^T [Wh_i || Wh_j]))

     You can extract these directly:
       _, attention_weights = self.conv1(x, edge_index, return_attention_weights=True)
       # attention_weights[0] = edge indices
       # attention_weights[1] = attention coefficients

     For each borrower, sort their neighbors by attention weight to
     find the most influential ones.

  B) GNNExplainer:
     Optimizes a mask M over features and edges:
       max I(y; x_M, A_M)  // mutual information between prediction and masked input

     Returns:
       - Feature mask: [0.9, 0.1, 0.8, 0.05, ...] (feature importance)
       - Edge mask: which edges in the computation graph matter

WHAT IT EXPLAINS:
  - "Which neighbors caused this borrower's risky GAT embedding?"
  - "Which features (income, CIBIL, overdue) drove the GNN's assessment?"
  - "Is the GAT focusing on meaningful connections or noise?"

WHY IT MATTERS:
  - This is the KEY link between your graph and your explainability claim
  - Shows the GAT isn't a black box — its attention mechanism IS
    an explanation
  - Reveals whether the contagion hypothesis is valid: does the GAT
    actually attend to risky neighbors?

XAI TECHNIQUE 4: Global Feature Importance (Permutation Importance)
───────────────────────────────────────────────────────────────────
WHAT IT IS:
  Measure how much each feature contributes to the RL agent's overall
  performance by shuffling one feature at a time and measuring the
  degradation in total recovery.

HOW IT WORKS:
  1. Run the trained PPO agent on the test set → record baseline reward
  2. For each feature f:
     a. Shuffle feature f across all borrowers (destroy its information)
     b. Run the agent again → record new reward
     c. Importance(f) = baseline_reward - shuffled_reward

  Example output:
    Feature Importance for RL Agent Performance:
    ┌─────────────────────────────────┬───────────┐
    │ Feature                         │ Importance│
    ├─────────────────────────────────┼───────────┤
    │ overdue_months                  │   23.5%   │
    │ cibil_score                     │   18.2%   │
    │ gat_embedding_3                 │   12.1%   │
    │ neighborhood_stress_1hop        │    8.7%   │
    │ gat_embedding_7                 │    6.4%   │
    │ coll_success_rate               │    5.9%   │
    │ community_risk_pct              │    4.8%   │
    │ income                          │    3.2%   │
    │ ...                             │    ...   │
    └─────────────────────────────────┴───────────┘

WHAT IT EXPLAINS:
  - "Which features does the RL agent rely on MOST?"
  - "Do the GNN embeddings actually matter for performance?"

WHY IT MATTERS:

XAI TECHNIQUE 8: Confidence Scores & Uncertainty Quantification
───────────────────────────────────────────────────────────────
WHAT IT IS:
  The PPO agent outputs action probabilities. Instead of just picking
  argmax, report the confidence:

    "Action: Field Visit
     Confidence: 78%  (P(Field Visit) = 0.78)
     Alternatives: SMS (15%), Legal (5%), No Action (2%)

     → High confidence: agent is sure Field Visit is best

    vs.

    "Action: SMS
     Confidence: 28%  (P(SMS) = 0.28)
     Alternatives: Field Visit (27%), Legal (25%), No Action (20%)

     → Low confidence: agent is uncertain — flag for human review"

HOW IT WORKS:
  PPO's policy network outputs a categorical distribution:
    π(a|x) = softmax(h(x))

  Where h(x) is the final layer logits. Extract these directly:
    action_dist = model.policy.get_distribution(obs)
    action_probs = action_dist.distribution.probs.detach().numpy()

  Then compute:
    - Confidence = max(action_probs)
    - Entropy = -Σ p * log(p)  (higher = more uncertain)
    - Margin = max_prob - second_max_prob

  Use entropy to flag uncertain decisions for human review.

WHAT IT EXPLAINS:
  - "How sure is the agent about this decision?"
  - When to trust the agent vs. escalate to a human

WHY IT MATTERS:
  - In production, you wouldn't want to blindly follow the agent's
    advice when it's uncertain
  - Adds a "human-in-the-loop" pathway for low-confidence decisions
  - Demonstrates the system knows when it doesn't know

INTEGRATION POINT 2: Counterfactual Explanations
─────────────────────────────────────────────────
File: NEW — xai_analysis.py (same file as SHAP)

Integration:
  - For a given borrower with observation x and chosen action a_chosen:
    1. Define target action a_target (next best alternative)
    2. Optimize x' to maximize π(a_target|x') while minimizing ||x'-x||
    3. Use L-BFGS or gradient descent with feature constraints

  Feature constraints:
    - age: can only increase (can't make borrower younger)
    - income: can increase or decrease within ±50%
    - cibil_score: can only increase (improving credit)
    - overdue_months: can only decrease (paying off debt)
    - GAT embeddings: treated as fixed (can't directly change embedding)

  Implementation sketch:
    def generate_counterfactual(obs, target_action, model, feature_bounds):
        x_cf = obs.clone()
        optimizer = torch.optim.LBFGS([x_cf], lr=0.1)

        def closure():
            optimizer.zero_grad()
            probs = policy_wrapper(x_cf.unsqueeze(0))
            loss = -torch.log(probs[0, target_action] + 1e-8)
            loss += 0.1 * torch.norm(x_cf - obs, p=1)  # minimality
            loss += constraint_penalty(x_cf, feature_bounds)
            loss.backward()
            return loss

        for _ in range(100):
            optimizer.step(closure)

        return x_cf

          return probs  # [P(NoAction), P(SMS), P(FieldVisit), P(Legal)]

  - In trajectory logging, include confidence:

      confidence = max(probs)
      entropy = -np.sum(probs * np.log(probs + 1e-8))
      is_uncertain = entropy > threshold  # e.g., threshold = 1.2

  - For production: flag uncertain decisions for human review
