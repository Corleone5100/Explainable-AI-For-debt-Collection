PART A: PROBLEM STATEMENT & MOTIVATION
================================================================================

PROBLEM:
  Debt collection agencies must decide WHICH action to take for EACH borrower
  to maximize recovered amounts while minimizing costs. Traditional approaches
  treat each borrower in isolation, ignoring the fact that borrowers influence
  each other through social and economic networks.

WHY GRAPH?
  Borrowers who share similar socioeconomic characteristics (same region,
  same occupation) tend to influence each other's financial behavior. If one
  defaults, their peers are more likely to default too — a phenomenon called
  "contagion." A graph captures these relationships explicitly.

WHY REINFORCEMENT LEARNING?
  Debt collection is a sequential decision-making problem:
    - The agency takes an action (SMS, field visit, legal notice)
    - The borrower responds (pays or doesn't)
    - The agency learns from the outcome
  RL is designed exactly for this: learn optimal policies through
  trial-and-error interaction with an environment.

WHY EXPLAINABLE AI?
  Financial decisions affect real people. Regulations (EU AI Act, US CFPB)
  require that automated decisions be explainable. Collection managers need
  to trust the system. Our GAT's attention mechanism provides natural
  explanations: "We chose Field Visit because this borrower's neighbors
  are highly delinquent."

INNOVATION:
  This project's key contribution is the Graph + RL hybrid:
    1. Build a borrower contagion graph using demographic similarity
    2. Train a GAT to learn node embeddings that encode neighborhood risk
    3. Feed these embeddings (plus structural features) to a PPO agent
    4. The agent learns collection strategies that account for BOTH
       individual borrower characteristics AND their network context

PART B: GRAPH CONSTRUCTION — THEORY & IMPLEMENTATION
================================================================================

B1. WHAT IS A GRAPH? (THEORY)
─────────────────────────────
A graph G = (V, E) consists of:
  - V: a set of vertices (nodes) — in our case, borrowers
  - E: a set of edges (links) — in our case, contagion relationships

Each node v ∈ V has a feature vector x_v ∈ R^d (8 borrower attributes).
Each edge (u, v) ∈ E may have a weight w_uv representing connection strength.

Why graphs for debt collection?
  Graph Neural Networks (GNNs) operate on graph-structured data. Unlike
  standard neural networks that process independent samples, GNNs use
  "message passing": each node aggregates information from its neighbors.
  This allows a node's representation to encode not just its own features
  but also the features of its surrounding neighborhood.

Types of graphs:
  - Homogeneous: single node type, single edge type (OURS)
  - Heterogeneous: multiple node/edge types
  - Directed vs undirected: OURS is undirected (contagion is symmetric)
  - Weighted vs unweighted: OURS is weighted (similarity-based)

B2. OUR NODES
─────────────
Each node represents a BORROWER (loan account holder).

Dataset: up to 200,000 borrowers from PostgreSQL table `master_env_data`.

Node features (8 dimensions per node):
  ┌─────────────────────┬──────────┬──────────────────────────────────────┐
  │ Feature             │ Type     │ Description                          │
  ├─────────────────────┼──────────┼──────────────────────────────────────┤
  │ age                 │ Numeric  │ Borrower's age                       │
  │ income              │ Numeric  │ Monthly/yearly income                │
  │ cibil_score         │ Numeric  │ Credit score (300-900 range)         │
  │ overdue_months      │ Numeric  │ Months the loan is overdue           │
  │ bounce_count        │ Numeric  │ Number of payment bounces            │
  │ coll_success_rate   │ Numeric  │ Historical collection success rate   │
  │ occ_idx             │ Categorical│ Occupation encoded as numeric index│
  │ reg_idx             │ Categorical│ Region encoded as numeric index    │
  └─────────────────────┴──────────┴──────────────────────────────────────┘

Preprocessing: All 8 features are standardized using StandardScaler
(mean=0, std=1) before being fed to the GAT.

B3. OUR EDGES — HOW WE CONNECT THEM
────────────────────────────────────
Edge Creation Rule: "Social Contagion Theory"

  Two borrowers are connected if they share BOTH:
    1. Same region (e.g., both in "R1")
    2. Same occupation (e.g., both are "Salaried" workers)

  Rationale: People who work in the same job and live in the same area
  are more likely to interact, share financial information, and influence
  each other's repayment behavior.

Algorithm:
  1. Group all borrowers by (region, occupation) pairs
     Example group: ("R1", "Salaried") → 50 borrowers
  2. Within each group, for each borrower i:
     - Randomly sample up to 5 neighbors from the same group
     - Create undirected edge (i, neighbor_1), (i, neighbor_2), ..., (i, neighbor_5)
  3. Remove duplicate edges (keep max weight if duplicates exist)

Why 5 neighbors?
  - Keeps the graph sparse (~5 edges per node on average)
  - Prevents combinatorial explosion (a clique of 50 nodes would have 1,225 edges)
  - Empirically sufficient for GNN message passing

Example:
  Group ("R1", "Self-employed"): 30 borrowers
  Each connects to 5 random peers from the same group
  Total edges ≈ 30 × 5 / 2 = 75 (divided by 2 because undirected)

B4. EDGE WEIGHTING SCHEME
──────────────────────────
Not all edges are equal. We assign a weight w(i,j) based on feature similarity:

  w(i,j) = 0.5 × income_similarity + 0.3 × age_similarity + 0.2 × same_risk

Where:
  income_similarity = 1 - |income_i_norm - income_j_norm|
  age_similarity     = 1 - |age_i_norm - age_j_norm|
  same_risk          = 1 if risk_category matches, 0 otherwise

  Values are min-max normalized to [0, 1] range.

Intuition:
  - Two borrowers with similar income have stronger contagion links
    (they face similar financial pressures)
  - Similar age → similar life stage → more interaction
  - Same risk category → already exhibiting similar behavior

Weight range: [0, 1] where 1 = maximum similarity.

B5. GRAPH STRUCTURAL FEATURES
──────────────────────────────
Beyond edges, we compute three node-level structural metrics using NetworkX:

  1. NODE DEGREE: Number of connections a borrower has.
     Intuition: Highly connected borrowers have more "exposure" to
     their neighbors' behavior.

  2. PAGERANK: Measures a node's importance in the graph.
     Intuition: A borrower with high PageRank is connected to other
     well-connected borrowers — they're "influential" in the network.
     Algorithm: Iterative scoring where a node's score depends on
     the scores of its neighbors (Google's original page ranking).

  3. BETWEENNESS CENTRALITY: How often a node lies on the shortest
     path between other nodes.
     Intuition: A borrower with high betweenness is a "bridge" between
     communities. If they default, the contagion might spread across
     otherwise disconnected groups.

B6. MULTI-HOP NEIGHBORHOOD SIGNALS
───────────────────────────────────
We compute the average overdue_months at multiple distances:

  signal_1hop(i) = mean(overdue_months of direct neighbors of i)
  signal_2hop(i) = mean(overdue_months of neighbors-of-neighbors of i)
  signal_3hop(i) = mean(overdue_months of 3-hop reachable nodes from i)

Implementation: Uses sparse matrix powers (A^2 for 2-hop, A^3 for 3-hop)
with torch_sparse for efficiency.

Why multi-hop?
  A borrower might have safe direct neighbors but be embedded in a
  risky broader community (friend-of-a-friend effect). The 2-hop and
  3-hop signals capture this "extended contagion" risk.

B7. GRAPH VALIDATION METRICS
─────────────────────────────
We validate the graph structure to ensure it's meaningful:

  ┌──────────────────────────┬──────────────────────────────────────────┐
  │ Metric                   │ What It Tells Us                         │
  ├──────────────────────────┼──────────────────────────────────────────┤
  │ Number of nodes          │ Total borrowers in the graph             │
  │ Number of edges          │ Total contagion links                    │
  │ Density                  │ How connected the graph is               │
  │ Connected components     │ Is the graph one piece or fragmented?    │
  │ Clustering coefficient   │ Do my neighbors also know each other?    │
  │ Degree assortativity     │ Do well-connected nodes connect to each  │
  │                          │ other? (positive = assortative)          │
  │ Same-risk edge ratio     │ What % of edges connect same-risk        │
  │                          │ borrowers? (>60% = graph aligns with     │
  │                          │ risk patterns)                           │
  └──────────────────────────┴──────────────────────────────────────────┘

B8. COMMUNITY DETECTION
───────────────────────
We use the Louvain algorithm to detect communities in the graph.

For each community, we compute aggregate risk metrics:
  - community_risk_pct: % of borrowers in the community who are High/Very High risk
  - community_avg_overdue: average overdue_months in the community
  - community_total_demand: total outstanding demand in the community
  - community_size: number of borrowers in the community

Each borrower inherits their community's metrics as features.

Intuition: "My entire community is struggling with debt" is a stronger
signal than just "my direct neighbors are struggling."

PART C: GRAPH ATTENTION NETWORK (GAT) — THEORY & TRAINING
================================================================================

C1. WHY GAT? (VS GCN, GRAPHSAGE)
─────────────────────────────────

  GCN (Graph Convolutional Network):
    - Treats ALL neighbors equally (uniform aggregation)
    - Problem: In debt collection, not all neighbors are equally influential.
      A Very High risk neighbor should matter more than a Very Low risk one.

  GraphSAGE:
    - Samples a fixed number of neighbors per hop
    - Good for large graphs and inductive settings (new unseen nodes)
    - But our graph is already sparse (~5 edges/node), so sampling adds
      no benefit and loses information

  GAT (Graph Attention Network) — OUR CHOICE:
    - Learns attention weights α(i,j) for each neighbor j of node i
    - The model automatically discovers which neighbors matter most
    - Perfect for contagion modeling: the GAT learns to attend to
      risky neighbors, which is exactly what we want
    - Transductive setting (all nodes known at training time) → GAT is ideal

C2. GAT ARCHITECTURE
─────────────────────
Our model: GATWithEmbedding (2-layer GAT)

  Layer 1: GATConv(8 → 32, heads=4)
    Input: 8-dimensional node features
    Output: 4 attention heads × 32 dimensions = 128 dimensions
    Activation: ReLU
    Regularization: BatchNorm1d + Dropout(0.3)

  Layer 2: GATConv(128 → 16, heads=1)
    Input: 128 dimensions (concatenated heads from Layer 1)
    Output: 16-dimensional node embeddings

  Classification Head: Linear(16 → 5)
    Maps embeddings to 5 risk category logits

  Total parameters: ~50,000 (lightweight)

C3. ATTENTION MECHANISM — THE MATH
───────────────────────────────────
For each node i and its neighbor j, the GAT computes an attention coefficient:

  Step 1: Linearly transform node features
    h_i = W · x_i    (W is a learnable weight matrix)

  Step 2: Compute raw attention score
    e_ij = LeakyReLU(a^T [h_i || h_j])

    Where:
      - a is a learnable attention vector
      - [h_i || h_j] is the concatenation of transformed features
      - LeakyReLU has negative slope 0.2

  Step 3: Normalize via softmax over all neighbors
    α_ij = softmax(e_ij) = exp(e_ij) / Σ_{k ∈ N(i)} exp(e_ik)

  Step 4: Aggregate neighbor features using attention weights
    h_i' = σ(Σ_{j ∈ N(i)} α_ij · h_j)

  Multi-head attention (Layer 1):
    - Run K=4 independent attention mechanisms
    - Concatenate outputs: h_i' = ||_{k=1}^K h_i^(k)
    - This stabilizes learning and captures different "aspects" of neighbors

C4. TRAINING PROCEDURE
──────────────────────
Task: Node Classification (predict risk_category from graph structure)

  Loss function: CrossEntropyLoss
  Optimizer: Adam (lr=0.005, weight_decay=1e-5)
  Epochs: 100
  Device: CUDA (GPU)

  Training loop:
    for epoch in 1..100:
      1. Forward pass: logits, embeddings, attention = model(x, edge_index, edge_attr)
      2. Compute loss: CrossEntropyLoss(logits, risk_labels)
      3. Backward pass: loss.backward()
      4. Update: optimizer.step()
      5. Track best model (lowest loss)

  The GAT is trained in a transductive setting — all nodes are visible
  during training. This is appropriate because our graph contains all
  known borrowers.

C5. OUTPUT: NODE EMBEDDINGS
────────────────────────────
After training, we extract 16-dimensional embeddings for every node:

  gat_embedding_0, gat_embedding_1, ..., gat_embedding_15

These embeddings encode:
  - The borrower's own 8 features (transformed)
  - Aggregated information from their neighbors (via attention)
  - Structural position in the graph

We also save attention weights:
  gat_attention_weights.csv: (source_node, target_node, attention_weight)

This file allows us to answer: "Which neighbors most influenced this
borrower's embedding?"

D1. WHAT IS REINFORCEMENT LEARNING? (THEORY)
─────────────────────────────────────────────
Reinforcement Learning (RL) is a machine learning paradigm where an agent
learns to make decisions by interacting with an environment.

Key concepts:
  - State (s): The current situation the agent observes
  - Action (a): What the agent can do
  - Reward (r): Feedback signal (positive = good, negative = bad)
  - Policy (π): The agent's strategy — maps states to actions
  - Episode: A complete sequence of interactions

The agent's goal: maximize cumulative reward over time.

Formally, RL problems are modeled as Markov Decision Processes (MDPs):
  MDP = (S, A, P, R, γ)
    S: state space
    A: action space
    P: transition probabilities P(s'|s,a)
    R: reward function R(s,a)
    γ: discount factor (future rewards are worth less)

D2. THE DEBTCOLLECTIONENV (GYMNASIUM ENVIRONMENT)
───────────────────────────────────────────────────
Our environment implements the Gymnasium API (formerly OpenAI Gym):

  class DebtCollectionEnv(gym.Env):
    - reset() → starts a new episode, returns initial observation
    - step(action) → applies action, returns (next_obs, reward, done, truncated, info)

The environment simulates the debt collection process:
  - Each step processes one borrower
  - The agent observes the borrower's 34-dimensional feature vector
  - The agent selects one of 4 actions
  - The environment computes the reward based on the action outcome
  - The episode ends after 100 borrowers

D5. REWARD FUNCTION — DETAILED BREAKDOWN
─────────────────────────────────────────
(See PART H for complete mathematical breakdown.)

The reward function balances recovery gains against action costs:

  reward = -action_cost + recovery_amount - wrong_action_penalty + contagion_bonus

Key components:
  1. Action cost: deducted immediately (varies by action and risk category)
  2. Recovery amount: probabilistic — depends on base recovery rate,
     collector success rate, and neighborhood stress factor
  3. Wrong action penalty: punishes mismatched action intensity
     (e.g., Legal Notice on a Very Low risk borrower)
  4. Contagion bonus: rewards collecting from influential borrowers
     in high-risk communities (this is where graph features directly help)

  - The agent observes each borrower, selects an action, receives reward
  - Episode ends after 100 steps
  - Training runs for 500,000 total timesteps (= 5,000 episodes)

PART E: THE RL ALGORITHM — PPO

E1. WHAT IS PPO? (THEORY)
──────────────────────────
PPO (Proximal Policy Optimization) is a policy gradient algorithm from
OpenAI / Stable Baselines3.

How it works:
  PPO maintains two neural networks:
    1. Policy network (π): maps observations → action probabilities
    2. Value network (V): maps observations → expected cumulative reward

  Training loop:
    1. Collect data: run the current policy for N steps (N=2048)
    2. Compute advantages: how much better was each action than expected?
       A(s,a) = R - V(s)  (Generalized Advantage Estimation)
    3. Update policy: maximize the PPO clipped objective

  PPO Clipped Objective:
    L(θ) = E[min(r(θ)·A, clip(r(θ), 1-ε, 1+ε)·A)]

    Where:
      r(θ) = π_new(a|s) / π_old(a|s)  (probability ratio)
      ε = 0.2 (clipping parameter)
      A = advantage estimate

  The clipping prevents the policy from changing too much in one update,
  which makes training stable compared to vanilla policy gradient methods.

E2. WHY PPO FOR THIS PROBLEM?
──────────────────────────────
  1. Stable training: PPO's clipping mechanism prevents catastrophic
     policy updates
  2. Good sample efficiency: makes efficient use of the 500K timesteps
  3. Handles discrete actions naturally (our 4-action space)
  4. Well-tested and reliable: Stable Baselines3 is a mature library
  5. Works well with VecNormalize (observation/reward normalization)

  Alternatives considered:
    - DQN: less stable, requires replay buffer, worse for continuous obs
    - A2C: simpler but less sample-efficient
    - SAC: designed for continuous actions, not needed here

E4. HOW PPO INTERACTS WITH OUR GRAPH FEATURES
──────────────────────────────────────────────
The PPO policy network is a standard MLP (not a GNN):
  - Input: 34-dimensional observation vector
  - Hidden layers: 2×64 neurons with tanh activation
  - Output: 4 action logits → softmax → action probabilities

The GNN's role is feature engineering, not policy architecture:
  - The GAT produces 16-dim embeddings that encode graph structure
  - These embeddings become part of the observation vector
  - PPO learns to use these embeddings in its policy

This separation is intentional:
  - The GNN captures spatial relationships (who influences whom)
  - The PPO captures sequential decision logic (which action to take)
  - Together, they produce a policy that is both graph-aware and
    action-optimized

The RL agent's observation space grows from 8 (original only) to 34
(original + graph features). Each dimension provides unique information:

  Original features tell the agent ABOUT THE BORROWER:
    "This borrower has low income, low CIBIL, 6 months overdue"

  Structural features tell the agent ABOUT THE BORROWER'S POSITION:
    "This borrower is well-connected (high degree) and bridges two
     communities (high betweenness) — their behavior influences many"

  Community features tell the agent ABOUT THE BORROWER'S CONTEXT:
    "This borrower's community is 70% high-risk — systemic problem"

  Multi-hop signals tell the agent ABOUT EXTENDED CONTAGION:
    "Direct neighbors look fine, but 2-hop out the average overdue
     is 8 months — risk is approaching from a distance"

  GAT embeddings tell the agent ABOUT LEARNED PATTERNS:
    "This borrower's embedding (which encodes their attended neighbor
     features) places them in a region of embedding space associated
     with high default probability"

F3. WHY GRAPH FEATURES HELP THE RL AGENT
─────────────────────────────────────────
Without graph features, the agent only sees individual borrower data:
  → "Borrower A: income=30K, CIBIL=550, overdue=4 → Legal Notice"

With graph features, the agent sees the network context:
  → "Borrower A: income=30K, CIBIL=550, overdue=4,
     but: community_risk=75%, 2-hop_stress=7.2, gat_embedding places
     them in a high-risk cluster
     → Field Visit (preemptive, before contagion spreads)"

The graph features enable the agent to:
  1. Prioritize influential borrowers (high PageRank, high betweenness)
     because collecting from them prevents wider contagion
  2. Escalate action for borrowers embedded in risky communities,
     even if individual features look moderate
  3. De-escalate for borrowers in healthy communities, even if
     individual features look concerning

F4. CONTAGION THEORY IN COLLECTION STRATEGY
────────────────────────────────────────────
The core hypothesis: default behavior spreads through social networks.

Evidence from research:
  - Augustin et al. (2021): "Contagious Distress" — loan defaults spread
    through social networks
  - Banerjee et al. (2013): diffusion in social networks affects financial
    behavior

Our system operationalizes this by:
  1. Building a graph that captures potential contagion pathways
  2. Using a GAT to learn which pathways are most influential
  3. Training an RL agent that internalizes contagion risk into its
     collection strategy

Global SHAP summary shows which features matter most across all decisions.

G3. COUNTERFACTUAL EXPLANATIONS

G4. CONFIDENCE SCORES & UNCERTAINTY
────────────────────────────────────
The PPO agent outputs action probabilities, from which we compute:
  - Confidence = max(probability) — how sure is the agent?
  - Entropy = -Σ p·log(p) — how uncertain is the policy?
  - Margin = top_prob - second_prob — how clear is the choice?

  High confidence (0.85): "Agent is sure about Field Visit"
  Low confidence (0.28): "Agent is uncertain — flag for human review"

PART H: REWARD FUNCTION — COMPLETE MATHEMATICAL BREAKDOWN
================================================================================

The reward for taking action a on borrower b is:

  R(b, a) = -cost(a, risk(b)) + recovery(b, a) - penalty(b, a) + contagion(b)

COMPONENT 1: ACTION COST
─────────────────────────
Cost depends on both the action AND the borrower's risk category:

  ┌──────────────┬──────────┬──────────┬───────────┬───────────┐
  │ Risk         │ No Action│ SMS/Call │ Field Vis │ Legal     │
  ├──────────────┼──────────┼──────────┼───────────┼───────────┤
  │ Very Low     │    0     │    30    │    300    │    800    │
  │ Low          │    0     │    30    │    300    │    800    │
  │ Medium       │    0     │    50    │    400    │    500    │
  │ High         │    0     │    80    │    500    │    250    │
  │ Very High    │    0     │    80    │    500    │    250    │
  └──────────────┴──────────┴──────────┴───────────┴───────────┘

  Note: Legal is cheaper for High/Very High risk (standardized process)
  but expensive for Low risk (overkill).

COMPONENT 2: RECOVERY AMOUNT
─────────────────────────────
Recovery is probabilistic:

  success_prob = base_recovery(a, risk) × coll_success_rate × stress_factor

  Where:
    base_recovery(a, risk):
      ┌──────────────┬──────────┬──────────┬───────────┬───────────┐
      │ Risk         │ No Action│ SMS/Call │ Field Vis │ Legal     │
      ├──────────────┼──────────┼──────────┼───────────┼───────────┤
      │ Very Low     │   0.0    │   0.4    │    0.7    │    0.3    │
      │ Low          │   0.0    │   0.4    │    0.7    │    0.3    │
      │ Medium       │   0.0    │   0.3    │    0.6    │    0.5    │
      │ High         │   0.0    │   0.15   │    0.65   │    0.7    │
      │ Very High    │   0.0    │   0.15   │    0.65   │    0.7    │
      └──────────────┴──────────┴──────────┴───────────┴───────────┘

    stress_factor = max(0, 1 - neighborhood_stress_1hop / 12)
      (If neighbors' average overdue is 12 months, stress_factor = 0 → no recovery)

  If recovery succeeds:
    recovered_amount = total_demand × uniform(low, high)

    ┌──────────────┬──────────┬────────────┐
    │ Action       │ Low %    │ High %     │
    ├──────────────┼──────────┼────────────┤
    │ SMS/Call     │   5%     │    15%     │
    │ Field Visit  │   15%    │    35%     │
    │ Legal Notice │   20%    │    40%     │
    └──────────────┴──────────┴────────────┘

COMPONENT 3: WRONG ACTION PENALTY
──────────────────────────────────
Penalizes mismatched action intensity:

  Very Low risk + Field Visit: -total_demand × 0.35  (wasteful)
  Very Low risk + Legal:       -total_demand × 0.50  (very wasteful)
  Low risk + Field Visit:      -total_demand × 0.25  (somewhat wasteful)
  Low risk + Legal:            -total_demand × 0.35  (wasteful)
  High/Very High + No Action:  -total_demand × 0.50  (missed opportunity)
  High/Very High + SMS/Call:   -total_demand × 0.40  (insufficient)

COMPONENT 4: CONTAGION BONUS
─────────────────────────────
Rewards collecting from influential borrowers in risky communities:

  IF community_risk_pct > 50:
    contagion_bonus = pagerank × total_demand × 0.1

  This teaches the agent to prioritize borrowers whose collection
  might prevent further defaults in their community.

PART J: POTENTIAL QUESTIONS FROM PROFESSORS (WITH ANSWERS)
================================================================================

Q1: "Why did you choose GAT over GCN or GraphSAGE?"
A1: GAT learns attention weights per neighbor, allowing the model to
    automatically discover which neighbors are most influential. GCN
    treats all neighbors equally, which is unrealistic for contagion
    modeling (not all neighbors are equally risky). GraphSAGE samples
    neighbors, but our graph is already sparse (~5 edges/node), so
    sampling loses information without computational benefit.

Q2: "How do you know your graph structure is meaningful?"
A2: We compute validation metrics:
    - Same-risk edge ratio: what % of edges connect same-risk borrowers?
      If >60%, the graph aligns with risk patterns.
    - Clustering coefficient: measures triangle density — high clustering
      indicates strong local contagion potential.
    - Modularity (via Louvain): measures community structure — high
      modularity confirms meaningful communities exist.

Q3: "Isn't the RL agent just a black box? How is this 'Explainable AI'?"
A3: We provide multiple explanation layers:
    - GAT attention weights show which neighbors influenced each embedding
    - SHAP analysis decomposes each RL decision into per-feature contributions
    - Counterfactuals show what minimal changes would alter a decision
    - Confidence scores flag uncertain decisions for human review
    - Policy visualizations show global behavior patterns
    The system is designed to be interpretable at every stage.

Q4: "Why use PPO instead of a GNN-based policy?"
A4: PPO with MLP is the standard approach for tabular/feature-based
    environments. The GNN's role is feature engineering — it produces
    embeddings that encode graph structure. The PPO agent then learns
    to use these embeddings in its policy. This separation is cleaner
    and more interpretable than an end-to-end GNN+RL architecture.

Q5: "How does the agent handle new borrowers not in the training graph?"
A5: Currently, the system is transductive — the GAT is trained on all
    known borrowers. For production, we would use an inductive GNN
    (GraphSAGE) that can generate embeddings for new borrowers by
    aggregating their neighbors' features without retraining. The RL
    agent would then use these embeddings directly.

Q6: "What if the graph edges are wrong? What if region+occupation isn't
     the right criterion for contagion?"
A6: This is why we compute graph validation metrics. If the same-risk
    edge ratio is low, it means our edge creation rule doesn't align
    with actual risk patterns. In that case, we would experiment with
    alternative edge rules (e.g., behavioral similarity, co-default
    timing, shared collector). The validation metrics tell us whether
    to trust the graph before we invest in GNN training.

Q7: "How does the reward function prevent the agent from always choosing
     the cheapest action (No Action)?"
A7: Multiple mechanisms:
    - Wrong action penalty: No Action on High/Very High risk borrowers
      incurs a penalty of -total_demand × 0.50
    - Recovery opportunity: SMS/Call/Field Visit/Legal all have positive
      expected recovery that can exceed their cost
    - Contagion bonus: rewards proactive collection from influential
      borrowers in risky communities
    The reward function is calibrated so that the optimal policy uses
    a mix of actions appropriate to each borrower's risk profile.

Q8: "What's the computational cost of this pipeline?"
A8:
    - Graph building: O(N × k) where N=200K, k=5 neighbors — ~1M edges
      Completed in ~10-15 minutes
    - GAT training: 100 epochs on a graph with 200K nodes, 1M edges
      On GPU: ~5-10 minutes
    - PPO training: 500K timesteps with VecNormalize
      On GPU: ~15-30 minutes
    Total: ~30-55 minutes for a full pipeline run

Q9: "Can you prove the graph features actually help?"
A9: Yes — through ablation studies. Train the PPO agent with:
    (a) Only original 8 features
    (b) Original + single neighborhood_stress_signal
    (c) Original + all graph features (34-dim)
    Compare total recovery across (a), (b), (c). If (c) > (b) > (a),
    we have evidence that graph features add value. We also use
    permutation importance to rank individual features by their
    contribution to agent performance.

Q10: "Is this deployable in production?"
A10: The current system is a proof of concept. For production:
     - The GAT would be retrained periodically as new borrower data arrives
     - GraphSAGE (inductive) would replace the transductive GAT to handle
       new borrowers without retraining
     - The RL agent would be wrapped in a decision support system (not
       fully autonomous — human-in-the-loop for low-confidence decisions)
     - Real-time inference: GAT embedding + PPO policy = <10ms per borrower

CONCLUSION:
  This project demonstrates a novel approach to debt collection that combines
  Graph Neural Networks with Reinforcement Learning. By modeling borrowers
  as a contagion graph and training a GAT to learn node embeddings, we
  provide the RL agent with rich network-level intelligence that traditional
  tabular approaches miss. The GAT's attention mechanism provides natural
  explanations for why certain borrowers are flagged for certain actions,
  fulfilling the "Explainable AI" promise of the project.

KEY CONTRIBUTIONS:
  1. A borrower contagion graph built on demographic similarity
  2. GAT-trained node embeddings that encode neighborhood risk
  3. A 34-dimensional observation space for the RL agent
  4. Multi-hop neighborhood stress signals (1-hop, 2-hop, 3-hop)
  5. Community-level risk metrics via Louvain detection
  6. Multiple explainability layers (attention, SHAP, counterfactuals)
  7. Policy visualizations for stakeholder communication

     pay off debts or fall further behind
  4. Multi-agent RL: Model multiple collection agents competing for
     resources (collectors)

     compare actual recovery rates against the RL agent's recommendations
  6. Fairness constraints: Add explicit regularization to prevent the

  7. Human-in-the-loop: Route low-confidence decisions to human reviewers
     and use their feedback to improve the policy
